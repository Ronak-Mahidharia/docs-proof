# Commands in the docs, run in a sandbox

Generated by `scripts/run_sandbox.py`. Don't edit by hand.

Each documented command that runs one of the project's own programs is run in a Docker container with no network, no Linux capabilities, and limits on processes, memory, and time. There's no shell: the program gets the documented words directly, so pipes and other programs in a line never run. Hooks loaded with Python stop the program right after its parser has read the command line, so nothing the command would do is done. The proof is the parser's own message.

## What ran

- **1,678 distinct command lines** from 2,743 documented commands in 26 repositories. 1 documented command wasn't run, because its words need the shell (such as `$(...)`).
- **Not run:** tox-dev/pipdeptree (its command line is written in Rust); nvbn/thefuck (it doesn't run on Python 3.14 at this commit: it imports distutils, removed in Python 3.12); and the two repositories with no command line.
- **As pinned:** the parser took the command line: 1,292; the parser refused it: 344; ran to the end: 23; stopped for another reason (such as reading a missing input): 19. Of the refusals, 322 are for an input the sandbox doesn't have or the docs leave out: a file, a required argument or value, a subcommand, or the network.

## The answer key

A command line is flagged when, after the planted change, the parser names a word it doesn't know that it didn't name before, or refuses a command line it took before.

| Split | Renamed option: cases | Lines | Flagged | False alarms | Precision | Recall | Read, not run: flagged |
|---|---|---|---|---|---|---|---|
| dev | 34 | 95 | 18 | 0 | 100.0% | 18.9% | 21 |
| test | 37 | 174 | 28 | 0 | 100.0% | 16.1% | 47 |

**Read, then run.** Of the renamed-option lines that reading the commands flags and running doesn't, 0 in dev and 19 in test are in commands the program still accepts after the change: argparse and optparse take a unique prefix of an option's name, so after a rename from `--x` to `--x2`, `--x` still works. 3 in dev and 0 in test are in commands that weren't run (their repository's program doesn't run in the sandbox) or were refused for another reason.

**Found only by running:**

- pypa/pipx:rename_env_var:1: docs/how-to/dependency-cooldown.rst:69. After the change, `pipx` refuses this command: argument --value/-V: invalid choice: 'PIPX_COOLDOWN'

Other kinds of change: 0 lines flagged in dev and 1 in test. Controls with a false alarm: 0 of 26 in dev, 0 of 28 in test.

## Limits

- A quoted argument that spans several lines isn't joined, so its command is read in pieces (3 of the audit's false alarms).
- A program that reads an internal command line with argparse before its own would be stopped early, and its command counted as accepted: that can hide a problem, but not make one up.
