# Suggested fixes

Generated by `scripts/run_fixes.py`. Don't edit by hand.

For each doc line the earlier steps flag, docs-proof suggests a fix and checks it before offering it. The rules fix what they can, working from the code before and after the change alone, and an agent takes the rest: a local model that works only by calling tools (read the doc, search the code, run a command in the sandbox), with a turn limit and loop detection. A fix may change at most 3 lines and must keep most of each one, and the flagged line must no longer say what the change removed or replaced. A fixed line in a documented command is run again in the sandbox, after the change, and the program must take it.

The flagged lines include the earlier steps' false alarms, and a fix offered for one of them would make a right line wrong. So nothing is changed without approval: the fixes become one patch to read, and a pull request is opened only after a person says yes to that patch.

The answer key's fix is the planted change made in the doc line: every mention of a renamed name becomes the new name (except inside a file path), and the old value becomes the new one. It was checked by hand, and 5 value lines needed a fix of their own ([data/hand_check.json](../../data/hand_check.json), "fixes").

## Limits

- **Rename fixes are right by design** wherever the rules make them: the key's fix is the same change, checked by hand. What's measured there is how often the rules can make one, and whether the program takes the fixed command.
- **A fix the program takes can still be wrong.** An agent made a command run by dropping the option that the doc's example was about, so the out-of-date lines' fixes are judged by hand.
- **The rules change only the old value.** They don't know that a minimum stated for PyPy is a Python version too, so after a rise from 3.10 to 3.12 they leave yt-dlp's "PyPy >=3.11".
- **Every false alarm got a fix,** from the rules or the agent. A fix is only as right as the flag it fixes, so each one needs a person's yes. Running step 3's model on the value search's flags first would remove some of them (3 of 10 on test).
- **The agent renames whatever it's given.** With every qwen3 prompt, it renamed another package's class (cookiecutter's `jinja2_time.TimeExtension`, 4 of 4 lines on dev), although the prompt from v2 on says the checker can be wrong.
- **The check that a fix keeps most of a line is loose.** On test, it let through a fix that cuts a line short (pipx's comparisons.rst:227) and one that drops a Markdown quote marker (mkdocs's plugins.md:117). A stricter check, that a fix changes the line only where the old name or value is, would have stopped both. It was found on test, so it waits for a new answer key (step 6) to be measured.
