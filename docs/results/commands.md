# Commands in the docs, checked against the code

Generated by `scripts/run_commands.py`. Don't edit by hand.

A documented command is a command in a code block, or in inline code, that runs one of the project's own programs: a console script, or `python -m` with one of its packages. It's read the way a shell reads it, and its long options are compared with the options the code declares. Nothing is run.

## Audit: the 30 repositories as pinned

- **2,868 documented commands**, 874 of them with long options.
- **Not checked:** tox-dev/pipdeptree, whose command line isn't declared in Python; Delgan/loguru and psf/requests have no command line.
- **Findings:** 5 options the code doesn't declare. Checked by hand ([data/hand_check.json](../../data/hand_check.json)): 0 out of date, and 5 false alarms: an option a plugin adds (3); a command the docs show failing on purpose (1); another program's option (1).

## The answer key: renamed options

A line is flagged when a documented command uses an option the change removed, with proof such as "`flask` declares no --host option in the code". Lines that mention the option outside a command (in a sentence, a list of options, or help output) are left to the exact checks, which flag every mention.

## Tried and not used

On dev it removed no false alarms and dropped a right line: `fuck --yeah`, the command thefuck sets up for itself.
